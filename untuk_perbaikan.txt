PERUBAHAN 2 - PERANCANGAN BASIS DATA / ERD (Gambar 3.24) narasi:

TEKS DI SKRIPSI=
Diagram erd menunjukkan struktur basis data dengan tiga entitas utama: admin, event, dan foto. entitas admin menyimpan data pengelola sistem dengan id admin sebagai kunci primer serta atribut username dan password. entitas event berisi informasi acara lari, meliputi id event sebagai kunci primer, nama event, jenis event, lokasi, dan tanggal event. entitas foto merekam dokumentasi unggahan dengan id foto sebagai kunci primer, file path, timestamp, nomor bib, dan face encoding untuk mendukung pencarian.
hubungan antarentitas diatur melalui tiga relasi utama dengan kardinalitas jelas. relasi mengelola menghubungkan admin dan event dalam pola one-to-many, artinya satu admin dapat mengelola banyak event sementara setiap event hanya dikelola oleh satu admin. relasi mengunggah mengaitkan admin dengan foto juga dalam pola one-to-many, sehingga seorang admin bisa mengunggah banyak foto.
Keterkaitan antara event dan foto dalam pola one-to-many, yang menunjukkan setiap event memiliki koleksi foto sedangkan satu foto hanya terkait pada satu event tertentu. rancangan ini memastikan entitas, relasi, dan atribut terintegrasi secara terstruktur untuk mendukung pencarian foto berdasarkan jenis event, timestamp, nomor bib, atau pengenalan wajah.

TEKS REVISI=
Perancangan basis data pada sistem ini menggunakan MongoDB yang bersifat dokumen (NoSQL), sehingga struktur penyimpanan digambarkan dalam bentuk collection dan dokumen, bukan tabel relasional. Rancangan konseptual data meliputi tiga collection utama, yaitu users, events, dan photos. Collection users menyimpan data pengguna dengan atribut _id, username, email, password, serta flag hak akses is_staff dan is_superuser yang membedakan pengguna biasa dan admin. Collection events menyimpan data event lari dengan atribut _id, nama event, jenis event, lokasi, dan tanggal event. Collection photos menyimpan data foto beserta metadata yang tertanam langsung di dalam dokumennya, meliputi _id, path file foto, nama event, folder, jenis event, timestamp, nomor bib, dan face encoding untuk mendukung pencarian.
Keterkaitan antar data direpresentasikan menggunakan pendekatan dokumen. Dokumen foto menyimpan referensi nama event dan folder tempat foto disimpan untuk menunjukkan event asal foto, tanpa menggunakan relasi kunci asing seperti pada basis data relasional. Metadata seperti jenis event, timestamp, nomor BIB, dan face encoding disimpan langsung (tertanam) pada dokumen foto sehingga setiap dokumen bersifat mandiri. Pengelolaan data event dan foto dilakukan oleh pengguna yang memiliki hak akses admin (ditandai is_staff atau is_superuser). Rancangan ini memastikan seluruh atribut terintegrasi secara terstruktur dan mendukung pencarian foto berdasarkan jenis event, timestamp, nomor BIB, atau pengenalan wajah.
